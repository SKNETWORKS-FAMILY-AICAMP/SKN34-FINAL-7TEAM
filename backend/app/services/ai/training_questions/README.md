# 질문 생성 담당자 준비

AI API를 연결하기 전에 질문 생성 → 행동 작성 → 총괄 검토의 입력·출력 형식과 실행 순서를 준비했습니다.

## 현재 가능한 작업

- 제공자를 주입받아 세 역할을 순서대로 호출합니다.
- 질문, 예상 행동, 안내 문구, 출처 ID, 불확실한 사항, 총괄 의견의 형식을 검사합니다.
- 허용된 행동과 제공한 자료 ID만 사용하도록 검사합니다. 메뉴를 담거나 메뉴 정보를 조회할 때는 해당 자료 ID가 인용돼야 합니다. 장바구니 항목 변경·삭제도 해당 항목 자료 ID를 요구합니다. 이 행동은 **실행하지 않는 제안**입니다.
- 수량은 1~99의 정수로 검사합니다. AI에 전달한 자료의 ID와 정리된 본문 SHA-256 해시를 기록하여 나중에 어떤 근거를 썼는지 추적할 수 있도록 합니다.
- 담당자 오류나 형식 오류가 나면 실패한 단계로 중단합니다.
- 총괄 담당자가 적절하다고 판단해도 사람의 최종 평가는 언제나 `pending`입니다.
- 출처에 AI가 생성한 가상 데이터라는 표식과 모델 식별자, 생성 시각을 기록합니다.

## 아직 연결되지 않은 작업

LLM 제공자 호출, 네트워크 통신, API 키, 실제 질문 생성, 자동 반복 실행, Streamlit 표시·저장 및 학습 데이터 내보내기는 연결하지 않았습니다. 테스트에 쓰는 고정 응답은 **테스트 전용**으로 실제 생성 결과가 아닙니다. 현재 사용자의 평가 기록과 기존 파일은 변경하지 않습니다.

## 나중에 연결할 제공자 계약

`Provider`의 `model_identifier`와 `complete(role=..., payload=...)`를 구현한 뒤 `generate_for_human_review(provider, scenario=..., source_facts=...)`에 전달합니다. `complete`는 JSON 객체로 파싱된 결과를 반환합니다. 각 역할의 형식과 허용 행동은 `workflow.py`에 명시합니다.

`source_facts`는 출처 ID와 자료 내용을 갖는 목록입니다. 메뉴·장바구니 조작에 사용하는 ID는 제공한 자료 ID와 일치해야 하며 `source_ids`에 포함되어야 합니다. 해시는 앞뒤 공백을 제거한 자료 텍스트의 UTF-8 바이트를 기준으로 계산합니다. 학습/검증/시험 분할은 호출자가 관리하며, 시험용 질문·정답은 생성 담당자에게 제공하지 않습니다. 개인정보나 API 키를 자료로 전달하거나 로그에 남기지 않습니다. 형식·출처 검사만으로 문장의 진실성과 알레르기 안전성까지 보장하지 않으므로 총괄 검토 후에도 사람이 확인합니다.
